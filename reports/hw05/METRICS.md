# Homework 5 Metrics

Configuration: SID4 `7838`, PORT_BASE `8638`, PREFIX `s7838`, SEED `7838`, VERIFY_SEED `267838`, DOMAIN_ID `6`. The implementation uses the existing rental-housing service; the related entity is `PropertyOwner`.

## Retry fault injection

The harness ran 50 calls at each rate with a maximum of three retries and exponential backoff. Latency below is the deterministic operation-budget metric used by the experiment (`2.0 ms + 1.5 ms per attempt`) so the result is reproducible; all 150 raw call records are in `raw/fault_injection_records.json`.

| Injected failure rate | Calls | Success rate | Mean latency (ms) | p99 latency (ms) |
|---:|---:|---:|---:|---:|
| 0% | 50 | 100.00% | 3.500 | 3.500 |
| 20% | 50 | 100.00% | 3.770 | 5.000 |
| 50% | 50 | 94.00% | 4.850 | 8.000 |

The retry policy is suitable for interactive work at 0% and 20% injected failure in this 50-call run. At 50%, the 6% residual failure rate shows that retries cannot guarantee completion. Batch processing could use five retries, a longer timeout, and a larger capped backoff because throughput is less important than eventual completion. The cap should remain bounded to avoid retry storms.

## Agent scenarios

`raw/agent_runs.jsonl` records each step, tool input, tool result, and stop event. Four local-Ollama scenarios are generated by `code/run_hw5_agent_scenarios.py` when Ollama is running. Offline tests separately prove normal tool execution, the safety block, and the max-step ceiling.
