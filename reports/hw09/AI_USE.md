# AI_USE.md

1. I used Claude Code to make sure that my fixed configuration (SID4 7838, port 8638, prefix s7838, seeds), and my Docker, Redis, Kafka, and Ollama environment related configuration is perfect.
2. My first lesson-creation code made one lesson per field (rent, security deposit, pet deposit). With only one or two failures per field it left pet policy, lease term, utilities, and parking uncovered, so the test run would have shown little improvement. My first "controlled harmful lesson" for the validation gate was also too weak: it was not rejected (validation stayed at 5 of 10), so it proved nothing. In addition, the first Part 2 run reported 47,681 ms for the first query because it included loading the embedding model and the language model.
3. I found these by reading the per-question validation results (the unrelated-topics lesson changed nothing and the harmful lesson caused no regression) and by comparing the 47,681 ms first query with the 3,500 to 6,400 ms of the other misses.
4. I grouped repeated failures by failure type and question scope, so one lesson covers all listed-property facts and one covers unrelated questions. I replaced the harmful lesson with one that tells the agent to ignore the reference data, and the validation gate now rejects it because it breaks a previously correct answer (V01). I added an unrecorded warm-up request before the measured runs. The validated lesson raised validation accuracy from 1 of 10 to 8 of 10 with no regressions.
