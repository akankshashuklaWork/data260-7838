# AI_USE.md

1. I used Claude Code to verify that I have not missed any important part of the HW8 requirements for eg - Kafka worker, FastAPI wrapper, three agents, Docker Compose file, failure-test harness, self-check script, and report generator, following the structure of my earlier homework folders. 
2. The first FastAPI wrapper created its Kafka producer and consumer when the module was imported, a pattern copied from the example project. With the installed aiokafka 0.15 this was wrong: the API container crashed at startup with "The object should be created within an async function" and kept restarting. A second problem appeared in the first demo run: merging client, API, and worker log lines by millisecond timestamp put the worker's "processing" line before its "received" line, which would have misdescribed the message flow.
3. I found the crash by running `docker ps` (the API container showed a fresh restart each time) and reading `docker logs s7838_api`, and I found the log-order problem by reading the first `homework_demo.py` output against the expected order of the ten required steps. I then verified the fix with a real CREATE_LISTING followed by GET_LISTING through Kafka, and with the self-check script, which tests that the same correlation_id comes back on every response.
4. I moved client creation into `KafkaRPC.start()`, which runs inside the event loop, and I rebuilt the image. I switched log timestamps to microseconds and made the API and worker log "sending ..." before they publish, so each line shows the order in which things happened. The API now starts cleanly, logs `FastAPI server started at http://127.0.0.1:8638`, and the demo prints send, receive, process, reply, and client-response lines in the correct order.
