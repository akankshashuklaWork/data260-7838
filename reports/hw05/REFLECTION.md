# Reflection

One representative offline run asked the bounded agent to find a listing. The harness first sent the user request together with a system contract requiring JSON actions and limiting the available tools to `search`, `detail`, and `aggregate`. On step one, the MockModel returned a search action for “San Jose.” The harness passed only that action’s JSON inputs to `execute_tool`, which validated the query and limit, applied the domain safety rule, and returned the shared `{ok, data, error}` envelope. The result was successful, so the harness appended both the tool call and its returned data to `agent_runs.jsonl`, then supplied the result back to the model as a tool message.

For the max-step test, the MockModel deliberately returned another search action after the first result instead of producing a final answer. The harness repeated the same validation and logging process on step two. Because the configured ceiling was two steps, it stopped after the second tool call and returned “Maximum tool steps reached.” The stop reason was `max_steps`, not a model exception or a safety violation. This distinction matters because the caller receives a clean final result while the JSONL record still shows exactly which actions consumed the budget. A separate safety test used a broad `all` search with a limit above ten; that call was rejected inside `execute_tool`, returned `ok: false`, and stopped the agent with `safety_rule_blocked` without raising an exception.
